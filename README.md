# 操作說明書

## 1. 先認識：哪些東西在哪裡改

整套系統分成兩邊：

| 在哪裡 | 管什麼 | 改完多久生效 |
| --- | --- | --- |
| **Google 試算表**「多帕周邊訂單」 | 活動、運送方式與運費、商品名稱與價格、上架與否、所有訂單 | 立刻（下一位客戶打開頁面就是新資料） |
| **GitHub 網頁檔案** `docs/` | 頁面文案、主視覺、開始 / 截止時間、數量上限、商品圖片與標籤、自訂題目 | 推送後約 1 分鐘 |

**Apps Script 程式（後端）所有活動共用，平常不需要改，也不用重新部署。**

> 後端**不檢查**開始 / 截止時間，也**不限制**購買數量，隨時都能下單與收款。
> 時間與數量的限制只在網頁上（前端）做。要「真正」停止收單，請看 [第 4 節最後](#真的要停止收單)。

試算表裡的工作表：

| 工作表 | 用途 |
| --- | --- |
| 活動設定 | 一個活動一列：活動代碼、訂單前綴、付款方式設定 |
| 運送方式 | 每個活動的取貨方式與運費 |
| 商品_活動代碼 | 該活動的商品、價格、是否上架 |
| 訂單_活動代碼 | 該活動的所有訂單（系統自動寫入） |
| 綠界通知紀錄 | 綠界每次通知的原始資料，對帳查問題用 |

## 2. 新增一個預購活動（表單）

以下用「2027 夏日周邊」為例，活動代碼取 `2027Summer`。

### 步驟 1：試算表「活動設定」加一列

| 欄位 | 填什麼 | 範例 |
| --- | --- | --- |
| 活動代碼 | 英文、數字、`-`、`_`。**會變成網址的一部分，之後不要改** | `2027Summer` |
| 活動名稱 | 會顯示在綠界付款頁 | `多帕2027夏日周邊` |
| 訂單前綴 | **剛好 4 碼**英文或數字，每個活動不要重複（訂單編號會是「前綴＋時間＋亂碼」共 20 碼） | `TS27` |
| 付款模式 | `aio`＝綠界自動收款（建議）；`donate`＝綠界贊助頁，人工對帳 | `aio` |
| 滿額免運 | 商品小計滿多少免運費，空白＝不免運 | `1500` |
| ATM繳費天數 | 空白＝1 天（綠界最短就是 1 天） | |
| 超商代碼繳費分鐘 | 空白＝1440 分鐘（1 天） | |
| 隱藏付款方式 | 綠界付款頁要隱藏的方式，見 [第 6 節](#6-運費與付款設定)。空白＝隱藏超商條碼 | |
| 贊助頁網址 | 只有 `donate` 模式要填 | |
| 備註 | 自己看的備註 | |

### 步驟 2：試算表「運送方式」加幾列

每一種取貨方式一列，活動代碼填同一個：

| 活動代碼 | 方式名稱 | 類型 | 運費 | 排序 | 啟用 |
| --- | --- | --- | --- | --- | --- |
| 2027Summer | 7-11店到店 | 超商 | 60 | 1 | ☑ |
| 2027Summer | 宅配 | 宅配 | 120 | 2 | ☑ |
| 2027Summer | 現場面交 | 面交 | 0 | 3 | ☑ |

「類型」決定表單要客戶填哪些資料：

| 類型 | 客戶要填（暱稱一律必填） |
| --- | --- |
| 超商 | 收件人姓名、手機、門市名稱（店號選填） |
| 宅配 | 收件人姓名、手機、收件地址 |
| 面交 | 收件人姓名、手機 |
| 免運送 | 不用填收件資料（電子檔、數位商品等） |

### 步驟 3：建立商品

1. 試算表**不用自己建**「商品_2027Summer」「訂單_2027Summer」工作表：
   - 第一次有人打開這個活動的網頁時，系統會自動建立；
   - 或到 Apps Script 編輯器（試算表選單「擴充功能 → Apps Script」）選 `setup` 按「執行」，立刻建立。
2. 在「商品_2027Summer」填商品，見 [第 3 節](#3-新增或修改商品)。

### 步驟 4：建立網頁

1. 複製整個 `docs/2026Birthday/` 資料夾，改名成 `docs/2027Summer/`（**資料夾名稱要和活動代碼完全一樣**）。
2. 修改以下內容：

| 檔案 | 要改的地方 |
| --- | --- |
| `config.js` | `id: '2027Summer'`、`formVersion: '2027Summer@1'`、`opens` / `deadline`、`maxQty`、`products`（圖片 / 標籤）、`questions`、`note`。`shipping`、`products` 的名稱與價格只是「頁面載入前先顯示」的備用資料，正式資料以試算表為準，但建議一起改成一樣 |
| `index.html` | `<title>`、`description`、`og:` 分享預覽、頁首主視覺圖、標題與介紹文字、「預購只到…」日期、三個步驟說明（付款 / 取貨方式）、預購須知、同意文字、頁尾、截止後顯示的文字（`id="closed"` 那段） |
| `thanks.html` | `<title>`、頁尾文字（其餘自動） |
| `img/` | 換成新的主視覺。建議寬 1200px、16:9、JPG，約 300KB 以內 |

> 表單欄位本身（暱稱、商品、取貨資訊、須知…）的版面在 `index.html` 的 `<form>` 裡，邏輯在共用的 `docs/assets/order-form.js`。**不用改共用檔案**；改了會影響所有活動。

### 步驟 5：加到表單總覽頁

在 `docs/campaigns.js` 最上面加一筆：

```js
{
  path: '2027Summer/',
  title: '多帕 2027 夏日周邊',
  desc: '一句話介紹',
  image: '2027Summer/img/key-visual.jpg',
  opens: '2027-07-01T20:00:00+08:00',     // 選填，未到時間顯示「即將開放」
  deadline: '2027-07-15T23:59:59+08:00'
},
```

總覽頁會依時間自動顯示「預購中 / 即將開放 / 已截止」。**這裡的時間只影響總覽頁的標示，表單頁本身以 `config.js` 為準，兩邊要填一樣。**

- [ ] 打開 `https://samoyedtopa1120-cmd.github.io/topa-store/2027Summer/`，商品、價格、運費和試算表一致

## 3. 新增或修改商品

商品都在試算表「商品_活動代碼」：

| 欄位 | 說明 |
| --- | --- |
| 商品代碼 | 英數字，例如 `ACRYLIC`。**上架後不要改**，網頁的圖片 / 標籤 / 數量上限靠它對應 |
| 商品名稱 | 顯示在表單、訂單、綠界付款頁 |
| 內容 | 表單上的小字說明 |
| 單價 | 整數，新台幣 |
| 上架 | 勾選＝販售中；取消勾選＝從表單上消失，也不能下單 |
| 排序 | 數字小的排前面 |

**常見操作：**

| 想做的事 | 怎麼做 |
| --- | --- |
| 新增商品 | 加一列並勾「上架」。重新整理表單就會出現（不用改網頁） |
| 改價格 / 名稱 / 說明 | 直接改試算表。**已成立的訂單金額不會變**，只影響之後的新訂單 |
| 暫停販售、從頁面拿掉 | 取消勾選「上架」 |
| 顯示「已售完」但保留在頁面上 | 網頁 `config.js` 的該商品加 `soldOut: true`（見第 4 節） |
| 加商品圖片 | 圖片放到活動資料夾的 `img/`，在 `config.js` 的 `products` 加上 `{ sku: '商品代碼', image: 'img/檔名.jpg' }` |
| 加「套組」「限定」等標籤 | `config.js` 的該商品加 `badge: '套組'` |

> 金額永遠由後端依試算表計算，客戶就算竄改網頁上的價格也沒用。

## 4. 前端限制：開始 / 截止時間、數量上限、售完

以下都在活動的 `config.js` 設定，**只限制網頁，後端不擋**。

### 開始 / 截止時間

```js
opens: '2027-07-01T20:00:00+08:00',     // 留空 '' = 一打開就能買
deadline: '2027-07-15T23:59:59+08:00',  // 留空 '' = 不截止
```

- 時間格式固定為 `年-月-日T時:分:秒+08:00`（`+08:00` 是台灣時間，不要漏）。
- 開始前：頁面顯示「預購尚未開始，將於 X 開放」。
- 截止後：頁面顯示 `index.html` 裡 `id="closed"` 那段文字（預設「預購已截止」）。
- 客戶如果在截止前就打開頁面、截止後才按送出，也會被擋下。
- 記得同步修改：頁首「預購只到…」文字、`docs/campaigns.js` 的時間。

### 數量上限

```js
maxQty: 10,     // 每一項商品最多買幾個
maxTotal: 0,    // 整張訂單最多幾件，0 = 不限
products: [
  { sku: 'BDAY-SET', badge: '套組', maxQty: 2 },   // 這個商品另外限制最多 2 個
  { sku: 'ACRYLIC' }
]
```

### 售完

```js
products: [
  { sku: 'MOUSEPAD', soldOut: true }   // 顯示「已售完」，不能選
]
```

如果不想讓它出現在頁面上，改成到試算表取消勾選「上架」。

### 真的要停止收單

前端限制擋得住一般客戶，但後端不鎖時間，懂技術的人仍可直接呼叫後端下單。要**確實**停止收單（例如活動結束、緊急下架），在試算表做任一項，後端就會拒絕新訂單：

- 把該活動所有商品的「上架」取消勾選；或
- 把該活動所有「運送方式」的「啟用」取消勾選。

**已成立的訂單仍然可以付款**，綠界的付款通知也照常回寫，不受影響。

## 5. 自訂題目與備註欄

在 `config.js` 的 `questions` 加題目，後端不用改：

```js
questions: [
  { label: '簽名要寫給誰', type: 'text', required: true, placeholder: '例：小明', maxLength: 30 },
  { label: '喜歡哪個角色', type: 'radio', options: ['多帕', 'Rocks'], required: true },
  { label: '想要的贈品', type: 'checkbox', options: ['貼紙', '小卡'] },
  { label: '尺寸', type: 'select', options: ['S', 'M', 'L'] },
  { label: '想說的話', type: 'textarea', hint: '會一起印在卡片上' }
],
note: { label: '備註', placeholder: '想對多帕說的話' }   // 不需要備註欄就寫 note: null
```

| type | 樣子 |
| --- | --- |
| `text` | 單行文字 |
| `textarea` | 多行文字 |
| `select` | 下拉選單 |
| `radio` | 單選 |
| `checkbox` | 複選 |

- `required: true` 為必填（只在網頁檢查）；`hint` 是題目下方的小字。
- 有題目時，表單會自動多出「其他問題」區塊，區塊編號自動調整。
- 答案存在訂單的「自訂欄位」，一題一行「題目：答案」；備註存在「買家備註」。
- 最多 30 題，每題答案最多 1000 字。

## 6. 運費與付款設定

### 運費

- 每種取貨方式的運費在「運送方式」工作表設定，可以不同。
- 「活動設定」的「滿額免運」：商品小計達到金額時，所有方式運費都變 0。
- 表單上的運費說明（例如「一律超商店到店，運費固定 NT$60」）會依設定自動產生。

### 付款方式

「活動設定」的「隱藏付款方式」用 `#` 分隔，常用代碼：

| 代碼 | 付款方式 |
| --- | --- |
| `Credit` | 信用卡 |
| `ATM` | ATM 虛擬帳號 |
| `CVS` | 超商代碼 |
| `BARCODE` | 超商條碼 |
| `WebATM` | 網路 ATM |
| `ApplePay` | Apple Pay |

- 空白＝`BARCODE`（預設隱藏超商條碼）；填「無」＝全部顯示。
- 為什麼預設隱藏超商條碼：綠界的條碼和超商代碼共用同一個「繳費期限」設定，但條碼以「天」計、代碼以「分鐘」計，同時開啟時條碼的期限會變成 1440 天。
- 實際可用的付款方式還取決於綠界帳號開通了哪些（例如目前不接受非台灣發行的信用卡）。

### 付款模式

- **`aio`（建議）**：綠界全方位金流 API，付款後自動驗證並把訂單改成「已付款」。
- **`donate`**：送單後到訂單頁，顯示應付金額與訂單編號，客戶到綠界實況主贊助頁自行填金額、在留言貼訂單編號付款，再按「我已完成付款」。系統只記錄「顧客回報付款」時間，**狀態維持付款中**；多帕到綠界後台比對贊助紀錄後，在試算表手動改成「已付款」。

## 7. 訂單管理：對帳、出貨、取消、退款

### 訂單狀態

| 狀態 | 什麼時候 | 誰改 |
| --- | --- | --- |
| 付款中 | 送出表單後；ATM / 超商代碼取號後也是付款中，並寫入「繳費資訊」「繳費期限」 | 系統 |
| 已付款 | 綠界通知付款成功（已驗證檢查碼與金額） | 系統 |
| 付款失敗 | 綠界通知付款失敗（例如刷卡被拒） | 系統 |
| 逾期未付 | 超過繳費期限，或刷卡頁面放著超過 2 小時沒付。**之後若真的付款，仍會自動改為已付款** | 系統 |
| 已取消 | 你手動選。之後綠界的任何通知都不會改掉，只會在「系統備註」提醒 | 人工 |
| 已退款 | 你手動選。同上 | 人工 |

- 對帳出貨時，用試算表的「篩選」只看「已付款」。
- 「系統備註」出現「金額不符」或「請人工確認」時，請到綠界廠商後台核對。

### 出貨

訂單工作表最右邊有給你用的欄位，系統不會寫入：「出貨狀態」（下拉選單：待出貨 / 已出貨 / 已送達 / 退回）、「出貨日期」、「物流單號」、「管理備註」、「折扣」。

客戶的訂單頁（感謝頁）可以隨時查看付款狀態。

### 取消與退款

1. **退款**：到綠界廠商後台對該筆交易退款（試算表的「綠界交易編號」可用來搜尋），完成後在試算表把狀態改成「已退款」。
2. **取消**（還沒付款的單）：直接把狀態改成「已取消」。

### 逾期未付的自動標記

系統在有人下單或查詢訂單時，會順便把逾期的訂單標成「逾期未付」。想要每小時固定檢查一次：

1. 試算表選單「擴充功能 → Apps Script」。
2. 左側「觸發條件」（鬧鐘圖示）→ 右下「新增觸發條件」。
3. 函式選 `sweepExpiredOrders`，事件來源「時間驅動」，類型「小時計時器」，每小時。
4. 儲存，依畫面授權。

### 其他

- 可以自行在訂單工作表加欄位、調整欄位順序、加顏色或篩選；系統依第一列標題找欄位，不會壞。**不要改第一列的欄位名稱**，也不要刪除系統欄位。
- 測試訂單可以直接刪除整列。
- 訂單含個資（姓名、手機、地址），出貨完成一段時間後建議刪除或匯出備份後刪除。

## 8. 怎麼修改網頁檔案

### 方法 A：在 GitHub 網頁上改（不用安裝任何東西）

1. 打開 https://github.com/samoyedtopa1120-cmd/topa-store ，進到 `docs/` 找到要改的檔案。
2. 按右上角鉛筆圖示（Edit）修改，完成後按「Commit changes」。
3. 約 1 分鐘後網站更新（Actions 分頁可以看到進度）。

新增活動資料夾時：進到 `docs/`，按「Add file → Create new file」，檔名輸入 `2027Summer/config.js`（輸入 `/` 會自動建立資料夾），把 `2026Birthday/config.js` 的內容貼上再修改；`index.html`、`thanks.html` 同樣做法。圖片用「Add file → Upload files」上傳到 `2027Summer/img/`。

### 方法 B：在電腦上改

```bash
git pull
# 修改 docs/ 底下的檔案
npm run dev        # 本機預覽 http://localhost:5173/，送單會進綠界「測試」付款頁
git add docs && git commit -m "新增 2027Summer 活動" && git push
```

本機預覽用的是假的試算表，裡面只有 2026Birthday 的資料；新活動的頁面在本機會顯示 `config.js` 的備用資料。

## 9. 常見問題

**Q：改了試算表的價格，網頁沒變？**
重新整理頁面。頁面會先顯示 `config.js` 的備用資料，1～3 秒後換成試算表的資料（Apps Script 剛睡醒時可能要多等幾秒）。

**Q：新活動頁面顯示「商品準備中」？**
「商品_活動代碼」裡沒有勾「上架」的商品，或活動代碼和資料夾名稱不一致（大小寫也要一樣）。

**Q：送單出現「找不到這個活動」？**
「活動設定」沒有這個活動代碼，或和 `config.js` 的 `id` 不一致。

**Q：送單出現「活動設定有誤（訂單前綴需為 4 碼英數字）」？**
「活動設定」的訂單前綴不是剛好 4 碼。

**Q：送單出現「請選擇取貨方式」？**
「運送方式」沒有這個活動的資料，或都沒勾「啟用」。

**Q：截止後還有人下單？**
前端截止擋不住直接呼叫後端的人。請照 [第 4 節](#真的要停止收單) 在試算表取消上架。

**Q：客戶說付款了，但狀態還是付款中？**
- 超商 / ATM 付款，綠界通知可能晚幾分鐘到一天。
- 到「綠界通知紀錄」用訂單編號搜尋，看有沒有收到通知、驗證是否「OK」。
- 到綠界廠商後台查該筆交易。確認已付款可以手動把狀態改成「已付款」。

**Q：網頁改壞了怎麼辦？**
GitHub 上每次修改都有紀錄：到該檔案按「History」找到之前的版本，複製舊內容貼回去。

**Q：什麼時候需要改 Apps Script？**
只有要改系統邏輯時（例如新增後端檢查、新的付款方式串接）。改完要重新部署，見 [技術說明](#技術說明)。

## 後端檢查項目

後端（Apps Script）在建單時會檢查：活動存在、訂單前綴 4 碼、取貨方式為啟用中、依取貨類型的必填欄位與格式、同意須知、商品存在且上架、數量為正整數、感謝頁網址在 `ALLOWED_ORIGINS` 白名單、防機器人隱藏欄位。金額一律依試算表重算。所有輸入以純文字寫入（防公式注入），並有長度上限。

綠界通知需通過檢查碼與商店代號驗證、金額相符；正式環境忽略「模擬付款」。查詢訂單需訂單編號＋32 碼查詢碼。

**不檢查**：開始 / 截止時間、購買數量、自訂題目必填、同一人重複下單、送單頻率。

## Apps Script API

| 方法 | 網址 | 呼叫者 |
| --- | --- | --- |
| POST | `/exec?action=createOrder` | 表單（JSON，`text/plain`） |
| POST | `/exec?action=reportPaid` | 贊助頁模式：客戶回報已付款 |
| POST | `/exec?action=ecpayNotify` | 綠界 ReturnURL（付款結果，伺服器對伺服器） |
| POST | `/exec?action=ecpayPaymentInfo` | 綠界 PaymentInfoURL（ATM／超商取號） |
| POST | `/exec?action=ecpayResult` | 綠界 OrderResultURL（客戶瀏覽器付款後導回，再轉到感謝頁） |
| GET | `/exec?action=orderStatus&campaign=&o=&t=` | 感謝頁查詢（需查詢碼 t） |
| GET | `/exec?action=campaign&campaign=` | 表單頁讀取商品、價格、運送方式（公開資訊） |

注意：`c`、`sid` 是 Apps Script 保留的參數名稱，不能使用。

## 部署步驟

### 1. 建立試算表與 Apps Script

**方法 A：手動（約 5 分鐘）**

1. 開新的 Google 試算表，命名「多帕周邊訂單」。
2. 擴充功能 → Apps Script。把 `gas/` 裡的 6 個 `.js` 檔各建一個同名檔案貼上（`Code.js` 貼到預設的 `程式碼.gs`）。
3. 專案設定 → 勾選「在編輯器中顯示 appsscript.json」→ 用 `gas/appsscript.json` 取代內容。
4. 上方函式選 `setup` → 執行 → 依指示授權。會建立活動設定、運送方式、訂單、商品、通知紀錄等工作表。

**方法 B：clasp**

1. 到 https://script.google.com/home/usersettings 開啟「Google Apps Script API」。
2. `npx @google/clasp login` 登入 Google。
3. `npx @google/clasp push --force` 推送程式碼（`.clasp.json` 已指向現有專案）。

### 2. 部署成網頁應用程式

1. 部署 → 新增部署作業 → 類型「網頁應用程式」。執行身分：**我**；誰可以存取：**所有人**。
2. 複製 `/exec` 網址：
   - 專案設定 → 指令碼屬性 → 新增 `WEBAPP_URL` = 該網址
   - 貼到各活動 `config.js` 的 `gasUrl`
3. 之後改程式碼要「管理部署作業 → 編輯 → 版本：新版本」，網址才會維持不變（clasp：`npx @google/clasp create-deployment -i <部署 ID>`）。部署後約 20 秒內可能仍是舊版本。

### 3. 測試 → 上線

預設 `ECPAY_ENV=stage`，使用綠界公開測試商店，不會真的扣款。測試信用卡 `4311-9522-2222-2222`、任意未過期日期、安全碼 `222`，簡訊驗證碼 `1234`。

上線時到指令碼屬性設定：

| 屬性 | 值 |
| --- | --- |
| `ECPAY_ENV` | `prod` |
| `ECPAY_MERCHANT_ID` / `ECPAY_HASH_KEY` / `ECPAY_HASH_IV` | 綠界廠商後台 → 系統開發管理 → 系統介接設定 |
| `ALLOWED_ORIGINS` | 改成你的網址，例如 `https://<帳號>.github.io` |

在編輯器執行 `showConfig` 可檢查設定（不會顯示金鑰）。

## 已知限制

- Apps Script 回應會先 302 轉址，綠界可能讀不到 `1|OK` 而重送通知。寫入已在第一次完成，重送不影響資料；若綠界後台持續顯示通知失敗，可在前面加一個 Cloudflare Worker 代為回 `1|OK`。
- `ecpayResult` 的自動跳轉頁在 Apps Script 沙盒中執行，若瀏覽器擋下自動跳轉，頁面上有「查看訂單」按鈕。
- 試算表結構有更新時（`gas/Config.js` 的 `SCHEMA_VERSION`），網頁應用程式會在下一次請求時自動補欄位，不會動到既有資料。
- 逾期標記刻意不用程式建立觸發器：新增觸發器權限會讓已部署的網頁應用程式需要重新授權。需要定時執行請手動在「觸發條件」新增（見第 7 節）。
