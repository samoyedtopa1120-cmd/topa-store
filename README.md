- 商品來源：買動漫賣場「薩摩耶之家」https://www.myacg.com.tw/seller_market.php?seller=552667
- 訂單試算表：Google 雲端硬碟「多帕周邊訂單」

# 操作說明書

## 1. 先認識：哪些東西在哪裡改

```
買動漫賣場 ──每天 05:00 自動同步──▶ 商品資料
                                      │
site/store.json（手動設定）───────────┤
                                      ▼
                     商店頁（所有周邊在同一頁）＋ 商品目錄
                                      │
           客戶下單 ──▶ Apps Script 依商品目錄計價 ──▶ 試算表「訂單」
```

| 在哪裡 | 管什麼 | 改完多久生效 |
| --- | --- | --- |
| **買動漫賣場** | 商品名稱、規格、價格、說明、主圖、庫存 | 每天台灣時間 05:00 自動同步；急的話可手動同步（第 8 節） |
| **`site/store.json`** | 商店上架哪些周邊、周邊的顯示名稱 / 首圖 / 截止時間、運費、付款設定、購買須知 | 存檔後約 2 分鐘（GitHub Action 自動重新產生） |
| **試算表「訂單」** | 所有訂單（系統寫入），出貨欄位你自己填 | 立刻 |

客人的流程：在商店頁點周邊 → 選規格和數量 → 按「完成」回到主頁 → 可以再點其他周邊 → 填一次收件資料 → 前往綠界付款。**不同周邊可以一起買，運費只收一次。**

> 後端**不檢查**開始 / 截止時間，也**不限制**購買數量，隨時都能下單與收款。
> 時間與數量的限制只在網頁上（前端）做。要「真正」停止收單，請看 [第 4 節最後](#真的要停止收單)。

## 2. 新增一個周邊

1. **在買動漫上架**，記下商品編號：商品網址 `goods_detail.php?gid=7819462` 的 `7819462`。
2. **在 `site/store.json` 的 `collections` 加一筆**（怎麼改見 [第 8 節](#8-怎麼修改設定手動同步)）：

   ```json
   {
     "myacgGid": 7900000,
     "title": "2027 夏日周邊",
     "summary": "一句話介紹，顯示在按鈕和視窗上",
     "deadline": "2027-07-15T23:59:59+08:00"
   },
   ```

3. 存檔後 GitHub Action 會自動重新產生網站資料，約 2 分鐘後商店頁就會出現新周邊。
   **如果是剛在買動漫上架的商品**，要等隔天 05:00 同步後才抓得到；想馬上上架請到 Actions 手動執行一次同步（第 8 節）。
4. 打開商店頁確認商品、價格正確，送一筆單看到綠界付款頁即可（不用付款）。

**周邊可以設定的欄位**（只有 `myacgGid` 必填，其他都可省略）：

| 欄位 | 說明 | 省略時 |
| --- | --- | --- |
| `myacgGid` | 買動漫商品編號 | 必填 |
| `title` | 按鈕與視窗上的名稱 | 買動漫標題（去掉「【多帕】」） |
| `summary` | 一句話介紹 | 不顯示 |
| `heroImage` | 只用這一張當首圖，相對網站根目錄的路徑（例 `img/summer.jpg`）或完整網址 | 用買動漫的所有商品圖 |
| `images` | 自訂多張圖（陣列），視窗裡可左右滑動 | 用買動漫的所有商品圖 |
| `description` | 「商品說明」的內容 | 買動漫的商品說明 |
| `opens` / `deadline` | 開始 / 截止時間，見第 4 節 | 不限制 |
| `hidden` | `true` = 暫時不顯示這個周邊 | 顯示 |
| `variants` | 個別規格的設定，見第 3 節 | 全部照買動漫 |

> 自己準備首圖：把圖片放到 `docs/img/`（建議寬 1200px、16:9、300KB 以內），`heroImage` 填 `img/檔名.jpg`。

## 3. 修改商品名稱、價格、規格

**一般情況直接在買動漫改**，隔天會自動同步過來（新增規格、改價、改說明都一樣）。

想讓商店頁顯示得跟買動漫不同時，在該周邊加 `variants`，用買動漫的**規格編號**對應（規格編號可在 `docs/data/myacg-products.json` 找到，每個規格的 `gid`）：

```json
"variants": {
  "7819462": { "name": "生日快樂之我全都要", "desc": "厚壓克力磚＋親簽明信片＋大滑鼠墊", "badge": "套組" },
  "7819463": { "name": "防身武器好安心", "maxQty": 2 },
  "7819464": { "hidden": true }
}
```

| 欄位 | 說明 |
| --- | --- |
| `name` / `desc` | 商店頁顯示的名稱、小字說明 |
| `badge` | 名稱旁的標籤，例如「套組」「限定」 |
| `price` | 覆寫價格（不建議，通常讓它跟買動漫一致） |
| `maxQty` | 這個規格最多買幾個（前端限制） |
| `soldOut` | `true` 顯示已售完；`false` 就算買動漫庫存 0 也照賣 |
| `hidden` | `true` 不在商店販售這個規格 |
| `sku` | 商品代碼，通常不用填（預設 `G` + 規格編號）。**上架後不要改** |

- 金額永遠由後端依商品目錄計算，客人竄改網頁上的價格也沒用。
- 改價只影響之後的新訂單，已成立的訂單金額不變。
- 買動漫庫存變 0 時，商店頁會自動顯示「已售完」（`store.soldOutWhenMyacgEmpty`）。

## 4. 前端限制：開始 / 截止時間、數量上限、售完

以下只限制網頁，**後端不擋**。

### 開始 / 截止時間（每個周邊各自設定）

```json
"opens": "2027-07-01T20:00:00+08:00",
"deadline": "2027-07-15T23:59:59+08:00"
```

- 格式固定 `年-月-日T時:分:秒+08:00`（`+08:00` 是台灣時間，不要漏）。省略 = 不限制。
- 開始前按鈕顯示「即將開放」，截止後顯示「已截止」，都可以點開看但不能選數量。
- 客人在截止前把商品加入、截止後才按送出，會被擋下並提示移除該周邊。

### 數量上限

在 `store` 設定（整間商店共用）：

```json
"maxQty": 10,
"maxTotal": 0
```

`maxQty` 是每個規格最多買幾個；`maxTotal` 是整張訂單最多幾件，0 = 不限。

單一規格另外限制：`variants` 裡加 `maxQty`（第 3 節）。

### 售完

- 買動漫庫存 0 → 自動顯示已售完。
- 手動：`variants` 裡加 `"soldOut": true`。
- 整個周邊下架：周邊加 `"hidden": true`。

### 真的要停止收單

前端限制擋得住一般客人，但後端不鎖時間，懂技術的人仍可直接呼叫後端下單。要**確實**停止某個周邊（例如活動結束、緊急下架），在 `site/store.json` 把該周邊加上 `"hidden": true` 或整筆刪掉；約 2 分鐘後網站更新，再最多 5 分鐘後端快取過期，就不能再下單。

**已成立的訂單仍然可以付款**，綠界的付款通知也照常回寫。

## 5. 自訂題目與備註欄

在 `site/store.json` 的 `store.questions` 加題目（整間商店共用，會出現在「其他問題」區塊），後端不用改：

```json
"questions": [
  { "label": "簽名要寫給誰", "type": "text", "required": true, "placeholder": "例：小明", "maxLength": 30 },
  { "label": "喜歡哪個角色", "type": "radio", "options": ["多帕", "Rocks"], "required": true },
  { "label": "想要的贈品", "type": "checkbox", "options": ["貼紙", "小卡"] },
  { "label": "尺寸", "type": "select", "options": ["S", "M", "L"] },
  { "label": "想說的話", "type": "textarea", "hint": "會一起印在卡片上" }
],
"note": { "label": "備註", "placeholder": "想對多帕說的話" }
```

| type | 樣子 |
| --- | --- |
| `text` | 單行文字 |
| `textarea` | 多行文字 |
| `select` | 下拉選單 |
| `radio` | 單選 |
| `checkbox` | 複選 |

- `required: true` 為必填（只在網頁檢查）；`hint` 是題目下方的小字；不需要備註欄就寫 `"note": null`。
- 答案存在訂單的「自訂欄位」，一題一行「題目：答案」；備註存在「買家備註」。

## 6. 運費與付款設定

都在 `site/store.json` 的 `store`：

| 欄位 | 說明 |
| --- | --- |
| `shipping` | 取貨方式清單：`name` 名稱、`type` 類型、`fee` 運費。**整張訂單只收一次運費** |
| `freeShippingOver` | 商品小計滿多少免運，0 = 不免運 |
| `paymentMode` | `aio`＝綠界自動收款（建議）；`donate`＝綠界贊助頁人工對帳 |
| `atmExpireDays` / `cvsExpireMinutes` | ATM / 超商代碼繳費期限，預設 1 天 / 1440 分鐘 |
| `ignorePayment` | 綠界付款頁隱藏的付款方式，`#` 分隔，預設 `BARCODE` |
| `notes` / `agreeText` / `footer` | 購買須知（`**文字**` 會變粗體）、同意文字、頁尾 |
| `orderPrefix` | 訂單編號前綴，**剛好 4 碼大寫英數字**，上線後不要改 |

取貨方式的 `type` 決定客人要填哪些資料：

| 類型 | 客人要填（暱稱一律必填） |
| --- | --- |
| 超商 | 收件人姓名、手機、門市名稱（店號選填） |
| 宅配 | 收件人姓名、手機、收件地址 |
| 面交 | 收件人姓名、手機 |
| 免運送 | 不用填收件資料（電子檔等） |

隱藏付款方式常用代碼：`Credit` 信用卡、`ATM` ATM 虛擬帳號、`CVS` 超商代碼、`BARCODE` 超商條碼、`WebATM` 網路 ATM、`ApplePay`。預設隱藏超商條碼是因為它和超商代碼共用「繳費期限」設定，單位卻不同（天 / 分鐘）。

`donate` 模式：送單後到訂單頁，顯示應付金額與訂單編號，客人到綠界實況主贊助頁自行填金額、在留言貼訂單編號付款，再按「我已完成付款」。系統只記錄回報時間，狀態維持付款中；多帕對帳後在試算表手動改成「已付款」。

## 7. 訂單管理：對帳、出貨、取消、退款

所有訂單都在試算表「訂單」分頁。「品項明細」每行前面有周邊名稱，例如 `【薩摩耶大量發生中】酒精瓶 x1`，跨周邊的訂單一眼就看得出來。「活動」欄是 `store`（商店）或 `2026Birthday`（舊的生日預購頁）。

### 訂單狀態

| 狀態 | 什麼時候 | 誰改 |
| --- | --- | --- |
| 付款中 | 送出表單後；ATM / 超商代碼取號後也是付款中，並寫入「繳費資訊」「繳費期限」 | 系統 |
| 已付款 | 綠界通知付款成功（已驗證檢查碼與金額） | 系統 |
| 付款失敗 | 綠界通知付款失敗（例如刷卡被拒） | 系統 |
| 逾期未付 | 超過繳費期限，或刷卡頁面放著超過 2 小時沒付。**之後若真的付款，仍會自動改為已付款** | 系統 |
| 已取消 | 你手動選。之後綠界的任何通知都不會改掉，只會在「系統備註」提醒 | 人工 |
| 已退款 | 你手動選。同上 | 人工 |

- 對帳出貨時，用「資料 → 建立篩選器」只看「已付款」。
- 「系統備註」出現「金額不符」或「請人工確認」時，請到綠界廠商後台核對。

### 出貨、取消、退款

- 訂單最右邊有給你用的欄位，系統不會寫入：「出貨狀態」（待出貨 / 已出貨 / 已送達 / 退回）、「出貨日期」、「物流單號」、「管理備註」、「折扣」。
- **退款**：到綠界廠商後台對該筆交易退款（用「綠界交易編號」搜尋），完成後把狀態改成「已退款」。
- **取消**（還沒付款的單）：直接把狀態改成「已取消」。

### 逾期未付的自動標記

系統在有人下單或查詢訂單時，會順便把逾期的訂單標成「逾期未付」。想每小時固定檢查：試算表「擴充功能 → Apps Script」→ 左側「觸發條件」→「新增觸發條件」→ 函式 `sweepExpiredOrders`、時間驅動、小時計時器 → 儲存並授權。

### 其他

- 可以在「訂單」分頁自行加欄位、調整順序、加篩選；**不要改第一列的欄位名稱**，也不要刪除系統欄位。
- 試算表裡的「活動設定」「運送方式」「商品」分頁已經**不再使用**（改由 `site/store.json` 與買動漫同步），確認不需要後可以刪除。
- 訂單含個資（姓名、手機、地址），出貨完成一段時間後建議刪除或匯出備份後刪除。

## 8. 怎麼修改設定、手動同步

### 修改 `site/store.json`（在 GitHub 網頁上）

1. 打開 https://github.com/samoyedtopa1120-cmd/topa-store/blob/main/site/store.json
2. 按右上角鉛筆圖示（Edit）修改，按「Commit changes」。
3. 到「Actions」分頁會看到「同步商品」開始執行，綠勾代表成功；約 1～2 分鐘後網站更新。
   **紅叉**代表設定有誤（例如少了逗號、訂單前綴不是 4 碼），點進去看錯誤訊息，修正後再存一次即可，網站不會被改壞。

> JSON 格式注意：字串要用雙引號、每筆之間要有逗號、最後一筆後面**不能**有逗號。不確定時可以貼到 https://jsonlint.com 檢查。

### 手動同步買動漫

「Actions」分頁 → 左邊選「同步商品」→ 右邊「Run workflow」→ Run。約 3～5 分鐘完成。

### 在電腦上操作

```bash
npm run sync     # 爬買動漫＋產生網站資料
npm run build    # 只依 site/store.json 重新產生
npm run dev      # 本機預覽 http://localhost:5173/，送單會進綠界「測試」付款頁
npm test
```

## 9. 常見問題

**Q：買動漫改了價格 / 新增規格，商店頁還沒變？**
每天 05:00 才同步。急的話到 Actions 手動執行「同步商品」。

**Q：新增了周邊，商店頁沒出現？**
- 確認 Actions「同步商品」是綠勾。
- 剛在買動漫上架的商品要先同步一次才抓得到（手動 Run workflow）。
- `myacgGid` 要填主商品編號（買動漫商品網址的 gid），不是規格編號。
- 有沒有不小心加了 `"hidden": true`。

**Q：送單出現「系統忙碌中（暫時讀不到商品資料）」？**
後端讀不到網站上的商品目錄（GitHub Pages 暫時異常）。通常幾分鐘內恢復；付款通知與訂單查詢不受影響。

**Q：截止後還有人下單？**
前端截止擋不住直接呼叫後端的人。照 [第 4 節](#真的要停止收單) 把周邊設為 `hidden`。

**Q：客人說付款了，但狀態還是付款中？**
- 超商 / ATM 付款，綠界通知可能晚幾分鐘到一天。
- 到「綠界通知紀錄」用訂單編號搜尋，看有沒有收到通知、驗證是否「OK」。
- 到綠界廠商後台查該筆交易。確認已付款可以手動改成「已付款」。

**Q：設定改壞了怎麼辦？**
GitHub 上每次修改都有紀錄：打開 `site/store.json` 按「History」，找到之前的版本複製回來。

**Q：什麼時候需要改 Apps Script？**
只有要改系統邏輯時（例如新增後端檢查、串接新的付款方式）。改完要重新部署，見技術說明。

# 技術說明

```
site/store.json              商店設定（手動維護）
docs/                        GitHub Pages 網站根目錄（Settings → Pages → main / docs）
  index.html, thanks.html    商店頁、訂單狀態頁
  assets/                    store.js / store.css（商店頁）、order-core.js（呼叫後端）、base.css
  data/myacg-products.json   買動漫爬蟲結果
  data/store.js              商店頁資料（自動產生）
  data/catalog.json          後端計價用的商品目錄（自動產生）
  assets/myacg/              買動漫商品圖（爬蟲下載）
  2026Birthday/              舊的生日預購頁（保留舊網址與訂單查詢連結）
gas/                         Apps Script 原始碼（Config / Campaign / Code / Ecpay / Sheet / Setup）
tools/
  crawl-myacg.mjs            買動漫爬蟲（遵守 robots.txt，請求間隔 5 秒）
  build-site.mjs             依 store.json ＋ 爬蟲結果產生 data/store.js、data/catalog.json
  dev-server.mjs             本機預覽（真的 gas 程式碼＋假試算表＋綠界測試環境）
.github/workflows/sync-store.yml   每日 05:00 同步；store.json 有修改時只重新產生
```

## 商品目錄與後端

- Apps Script 下單時用 `UrlFetchApp` 讀 `data/catalog.json`（快取 5 分鐘，另有 6 小時備份快取），依目錄計價。
- 付款通知（ecpayNotify / PaymentInfo / Result）與訂單查詢**不依賴**商品目錄，目錄讀不到也能正常收款。
- 目錄網址可用指令碼屬性 `CATALOG_URL` 覆寫。
- 第一次使用（或權限變更後）：在 Apps Script 編輯器選 `testCatalog` 執行並授權「連結外部服務」。

## 後端檢查項目

建單時檢查：活動存在、訂單前綴 4 碼、取貨方式存在、依取貨類型的必填欄位與格式、同意須知、商品存在於目錄、數量為正整數、感謝頁網址在 `ALLOWED_ORIGINS` 白名單、防機器人隱藏欄位。金額一律依目錄重算。所有輸入以純文字寫入（防公式注入），並有長度上限。

綠界通知需通過檢查碼與商店代號驗證、金額相符；正式環境忽略「模擬付款」。查詢訂單需訂單編號＋32 碼查詢碼。

**不檢查**：開始 / 截止時間、購買數量、自訂題目必填、同一人重複下單、送單頻率。

## Apps Script API

| 方法 | 網址 | 呼叫者 |
| --- | --- | --- |
| POST | `/exec?action=createOrder` | 商店頁（JSON，`text/plain`） |
| POST | `/exec?action=reportPaid` | 贊助頁模式：客人回報已付款 |
| POST | `/exec?action=ecpayNotify` | 綠界 ReturnURL（付款結果，伺服器對伺服器） |
| POST | `/exec?action=ecpayPaymentInfo` | 綠界 PaymentInfoURL（ATM／超商取號） |
| POST | `/exec?action=ecpayResult` | 綠界 OrderResultURL（客人付款後導回，再轉到訂單頁） |
| GET | `/exec?action=orderStatus&campaign=&o=&t=` | 訂單頁查詢（需查詢碼 t） |
| GET | `/exec?action=campaign&campaign=` | 商品目錄中的公開資訊 |

注意：`c`、`sid` 是 Apps Script 保留的參數名稱，不能使用。

## 部署

1. **推送程式碼**：`npx @google/clasp push --force`（`.clasp.json` 已指向現有專案）。
2. **新權限要先授權**：程式用到新的 Google 權限時，先在編輯器執行一次函式授權（例如 `testCatalog`），再部署，避免線上服務中斷。
3. **部署到同一個網址**：`npx @google/clasp create-deployment -i <部署 ID>`，或在編輯器「管理部署作業 → 編輯 → 版本：新版本」。部署後約 20 秒內可能仍是舊版本。

指令碼屬性：

| 屬性 | 值 |
| --- | --- |
| `ECPAY_ENV` | `prod`（預設 `stage` 為綠界測試環境） |
| `ECPAY_MERCHANT_ID` / `ECPAY_HASH_KEY` / `ECPAY_HASH_IV` | 綠界廠商後台 → 系統開發管理 → 系統介接設定 |
| `ALLOWED_ORIGINS` | 允許下單的網站，例如 `https://<帳號>.github.io` |
| `WEBAPP_URL` | 部署後的 `/exec` 網址（綠界回傳用） |
| `CATALOG_URL` | 選填，商品目錄網址 |

在編輯器執行 `showConfig` 可檢查設定（不會顯示金鑰）。綠界測試環境測試卡：`4311-9522-2222-2222`、任意未過期日期、安全碼 `222`、簡訊驗證碼 `1234`。

## 已知限制

- Apps Script 回應會先 302 轉址，綠界可能讀不到 `1|OK` 而重送通知。寫入已在第一次完成，重送不影響資料。
- `ecpayResult` 的自動跳轉頁在 Apps Script 沙盒中執行，若瀏覽器擋下自動跳轉，頁面上有「查看訂單」按鈕。
- 買動漫改版可能讓爬蟲抓不到資料；此時 Action 會失敗、不覆蓋舊資料，商店維持前一天的內容。
- 試算表結構有更新時（`SCHEMA_VERSION`），網頁應用程式會在下一次請求時自動補欄位，不會動到既有資料。
- 逾期標記刻意不用程式建立觸發器，需要定時執行請手動在「觸發條件」新增（第 7 節）。
